# Contributing to noteberry

This is a simple contribution guide, since the project is not mature
enough to need extensive and detailed guide

# Code of Conduct

By participating in this project, you agree to abide by our Code of Conduct. Please be respectful and collaborative.

## How can I Contribute?

### Reporting Bugs

- Search existing issues before opening a new one.
- Use a clear, descriptive title.
- Include steps to reproduce the bug.
- Describe the expected vs. actual behavior.

### Suggesting Enhancements

- Open an issue explaining the feature and why it is needed.
- Provide examples or use cases for the enhancement.

### Submitting Pull Requests (PRs)

1. **Fork** the repository and create your branch from `main`.
2. Ensure your code follows the project's styling and formatting rules.
3. Write clear, structured git commit messages.
4. Update the documentation (`README.md`) if your changes alter functionality.
5. Issue a Pull Request against the `main` branch.

### 3. Style Guide & Standards

NOTE: As the codebase is still mature anything detailed in this section might change in the future.

- _Code Style_:
  - for now read the codebase, it has a certain way of doing certain things
  - I'll outline the style guide when I have a decided clear way of how the project should go
- _Testing_:
  - Run tests before submitting changes
  - Add missing tests if your changes do not have the relevant tests
- _Feature Branches_:
  - This codebase is currently following feature branching conventions
  - Because it makes it easier to track changes, review PRs, and version the codebase
- _Commits_: conventional commits is the main way to write commit messages in this codebase
